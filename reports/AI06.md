# Retrieval baseline comparison

## Question

Does TF-IDF improve retrieval of the intended experiment over BM25 and unique keyword overlap, when method selection uses development questions before frozen confirmation evaluation?

## Method

All methods search the same ten saved experiment records from four companion studies. They index title plus full evidence text, including limitations, using the existing lowercase ASCII tokenizer and stopword set. They return only positive scores, break ties by ascending source ID, and report cutoffs one and three. Source IDs, URLs and artifact/text hashes remain in the unchanged registry; the protocol records its exact byte digest.

BM25 retains k1=1.2 and b=0.75 and its existing positive IDF formulation. Keyword overlap counts unique query terms present in the document. TF-IDF uses raw document term frequency, binary query term frequency, IDF = 1 + ln((N+1)/(df+1)), and cosine similarity with IDF applied to both vectors. Vocabulary and document frequencies come only from registry documents. Out-of-vocabulary query terms are discarded. Empty vectors return no results. These are explicit weighting choices within the [TF-IDF](https://nlp.stanford.edu/IR-book/html/htmledition/tf-idf-weighting-1.html) and [cosine vector retrieval](https://nlp.stanford.edu/IR-book/html/htmledition/queries-as-vectors-1.html) framework, not a claim of reproducing every textbook variant. Scores are relevance weights, not comparable confidence probabilities. Recorded scores are rounded to ten decimal places after ranking to suppress summation noise.

The existing thirteen studio questions were copied without changing their labels into `experiments/AI06-development.json`: ten expected-source questions, two unrelated topics and one misleading overlapping question. The selection rule was fixed before measuring these questions: maximize source recall at one, then at three, then minimize unsupported nonempty retrieval; ties prefer BM25, then TF-IDF, then overlap. BM25 tied TF-IDF and was retained by this rule, without evidence of superiority between them.

Next, `experiments/AI06-freeze.json` bound the measured development artifact, development questions, registry, all three retrievers, evaluator and earlier confirmation questions to byte hashes. Only then were fourteen new source-aware questions authored: one answerable question per source, two unrelated topics and two absent measurements with overlapping vocabulary. Exact source excerpts anchor answerable labels. The complete question set and labels were sealed together with the freeze manifest before any confirmation retrieval. No rules or labels were changed after evaluation, and confirmation cannot reselect the method. Loading rejects input drift, reused question text, invalid anchors and inconsistent source coverage. Earlier confirmation outcomes were visible; this is a fresh wave independent of selection, not independent human or blinded authorship.

## Actual findings

| Phase and measure | BM25 | TF-IDF | Keyword overlap |
| --- | ---: | ---: | ---: |
| Development source recall at 1 | 10/10 | 10/10 | 8/10 |
| Development source recall at 3 | 10/10 | 10/10 | 10/10 |
| Development unsupported nonempty retrieval | 1/3 | 1/3 | 1/3 |
| Development empty unsupported retrieval | 2/3 | 2/3 | 2/3 |
| Confirmation source recall at 1 | 10/10 | 10/10 | 9/10 |
| Confirmation source recall at 3 | 10/10 | 10/10 | 10/10 |
| Confirmation unsupported nonempty retrieval | 3/4 | 3/4 | 3/4 |
| Confirmation empty unsupported retrieval | 1/4 | 1/4 | 1/4 |
| Confirmation empty answerable retrieval | 0/10 | 0/10 | 0/10 |

TF-IDF adds no source hits over BM25 on these questions. Keyword overlap ranks the stable variance source second on c09, a question about stable conditions and observed interval coverage. Its first result is the shifted source, which shares most of its text. This is a wrong-source miss at rank one, not empty retrieval; rank three recovers the intended source. Development and confirmation are reported separately rather than pooled.

Both deliberately overlapping unsupported requests retrieve records: battery voltage for the Hubbard dimer and network nanoseconds for the trading simulation. The source limitations explicitly exclude those measurements. More unexpectedly, c14 asks about cetacean echolocation in seawater and retrieves all three market records solely through the generic term **through**, which is absent from the fixed stopword list. Its unrelated-topic label remains unchanged. The archaeology question c13 returns nothing. Thus the unrelated stratum has one nonempty and one empty result; the misleading-overlap stratum has two nonempty and zero empty results. The full rankings, scores and rationales remain in [the ledger](../results/AI06-baselines.json).

For these exact implementations, every in-vocabulary matched term contributes positively under all three scoring rules. With the same fields, tokenizer and positive-score filter, they consequently have the same nonempty-versus-empty boundary. Weighting can change source order but cannot improve this any-hit false support proxy. This explains the equal unsupported outcomes; it does not establish that all retrieval methods share this limitation. Nonempty retrieval of an explicitly rejecting limitation may be useful evidence, but it still cannot supply the requested absent measurement.

The eighth studio case, **Retrieval baseline comparison** (`#retrieval-baselines`), exposes separate development and confirmation recall charts, unsupported/empty counts, the fixed selection rule and all 81 question-method rows. Each row contains expected and ranked source IDs, scores, first expected rank, outcome, label rationale and confirmation source anchors. Existing chart toggles and CSV export work through the studio's standard renderer. The evidence explorer keeps its established BM25 behavior.

## Reproduce

```bash
python -m src.baseline_study --development --output results/AI06-development.json
python -m src.baseline_study --output results/AI06-baselines.json
python lab.py --output results/latest.json
python src/studio.py --out docs/study.json
python src/studio.py --check docs/study.json
python -m unittest discover -s tests -v
python quality/contract.py --project . --name ai-research-workbench --task-id AI06
```

The development-only command does not read confirmation files. Reproduction reruns the already frozen experiment; it cannot recreate unobserved questions or erase prior exposure. Serve `docs` with the README command and open `/#retrieval-baselines`. No additional dependency, source refresh or inference service is required.

Tests check an independently calculated TF-IDF cosine, corpus-only vocabulary/IDF, binary query weighting, empty vectors, OOV tokens, stopwords, deterministic ties, selection tie rules, development execution without any confirmation files, every frozen/sealed input's drift rejection, source anchors, question reuse, source coverage, saved-result agreement and studio rows. At each cutoff, answerable hits plus wrong-source misses plus empty misses equal the answerable count; unsupported nonempty plus unsupported empty equals its separate denominator.

## Limitations

These small authored questions were written with knowledge of the source records and earlier results. Exact excerpt anchors make labels inspectable but do not independently establish semantic correctness. Near-duplicate case text and explicit case qualifiers make many questions easy. The observed tie does not establish general equivalence, statistical superiority or deployment accuracy. Do not compare the development and confirmation unsupported rates as a system deterioration: their question mixtures differ, and all rules stayed fixed.

The saved records describe synthetic studies. Retrieval does not validate their scientific conclusions, live profitability, physical hardware performance or scalability. Negative companion findings, including worse expanding-ridge MAE and negative paired quoting improvement, are preserved. No answer-generation quality, model inference, latency, operation-count advantage or infrastructure cost is measured. All methods have identical evidence access; no monetary cost assumptions are needed. Hashes expose changes relative to saved local manifests, not authenticated history or external timestamps. Changing weights, stopwords or thresholds requires a new protocol and fresh confirmation questions.

Explain the binary query/raw document TF choice and why score scales cannot be compared across methods. Trace development selection, code freeze, question authoring, sealing and evaluation as separate steps; explain why a tie retains BM25 without proving it better. Reproduce c09's wrong-source rank-one miss and c14's accidental overlap through a generic term. Show why all-positive lexical weights preserve the nonempty retrieval boundary, and distinguish source recall, unsupported retrieval, empty retrieval and generated-answer correctness. Explain what an anchor and a hash can establish, and what they cannot.
