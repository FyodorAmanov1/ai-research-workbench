# Registry freshness audit

## Question

Can an evidence interface detect changes outside its indexed record text, refresh explicit source artifacts safely, and still reproduce earlier claims when cases change or disappear?

## Method

The applied registry contains ten saved records from four companion studies. Source-artifact SHA-256 fields identify whole artifacts, while record SHA-256 fields identify only indexed evidence text. The refresh implementation now compares the explicit prior artifact digest with the exact newly read source bytes. It reads only the four allowlisted study paths supplied by the caller and makes no network request.

For controlled measurement, each saved record's complete text and typed metrics are placed in a synthetic study envelope. These are projections, not recovered original source files. Ten independent scenarios start from the same fixture: unchanged bytes, formatting only, source metadata outside the projection, metric edit, added case, removed case, missing file, malformed JSON, wrong project identity and duplicate case ID. The comparison baseline checks the source's map of case IDs to indexed-text hashes. Both methods see the same valid source observations; invalid or unavailable inputs produce unknown freshness rather than an invented change label.

Refresh reports source status, old/new digests, old/new IDs and record-level added/removed/changed/unchanged states. Unchanged record text can coexist with stale source bytes. Missing or invalid sources and absent or ambiguous prior digests block replacement. Every refresh archives the exact prior registry before publishing a candidate. Content-addressed history also retains all newly observed source bytes, the candidate and the audit. A same-directory temporary file provides atomic active-registry replacement after archival; this is not a multiwriter transaction or a power-loss durability guarantee.

Stable case IDs are preserved across versions. Removed IDs remain accessible in exact old snapshots alongside their full recorded text, methods, limitations, typed metrics and provenance. Original artifact bytes that were never archived are explicitly marked unavailable; they cannot be reconstructed from a projection. Once a source version has been observed and archived, later refreshes can retain and identify those exact old bytes. Empty source case collections retain their artifact digest in an additive source map for future checks.

The conceptual distinction between stable resources and specific revisions follows [W3C PROV-DM](https://www.w3.org/TR/2013/REC-prov-dm-20130430/). This is a small JSON history implementation, not a claim of PROV serialization conformance or authenticated provenance.

## Actual findings

| Controlled outcome | Artifact-byte audit | Indexed-text baseline |
| --- | ---: | ---: |
| Changed valid artifacts detected | 5/5 | 3/5 |
| Unchanged artifact flagged as changed | 0/1 | 0/1 |
| Unavailable or invalid sources | 4 unknown; replacement blocked | 4 unknown |

The text-only baseline misses both source metadata outside the indexed projection and a formatting-only edit. The full-artifact audit detects both. Formatting changes do not imply changed scientific conclusions; this deliberate conservative flag is retained as a limitation. Both methods detect changed metric text, case additions and removals. All ten expected audit decisions match specification; all ten exact prior registries are retained. For each blocked refresh, the active file remains byte-identical. After the initial fixture observation, all ten scenarios also retain their prior raw source versions.

The metric edit is a synthetic perturbation of a saved metric, not a new experiment result. Earlier scientific findings remain untouched, including the failure of expanding ridge to improve on frozen ridge and lexical false support on misleading questions. No companion simulation or live source survey was performed.

The fifth studio case exposes the measured baseline comparison, scenario selector, old/new hashes, source IDs and record-change ledger, with the existing CSV export. It can also inspect a user-selected local refresh audit JSON without uploading it. Imported audit data is labelled user-provided; its old-registry fingerprint is compared with the bundled measurement, without claiming authentication or current freshness. The frozen registry, retrieval rules and browser retriever remain unchanged.

## Reproduce

```bash
python -m src.freshness_study --output results/AI03-freshness.json
python -c "from pathlib import Path; Path('docs/freshness-study.json').write_bytes(Path('results/AI03-freshness.json').read_bytes())"
python lab.py --output results/latest.json
python src/studio.py --out docs/study.json
python src/studio.py --check docs/study.json
python -m unittest discover -s tests -v
python quality/contract.py --project . --name ai-research-workbench --task-id AI03
```

For an actual offline refresh, replace `SOURCE_DIRECTORY` with a directory containing the four named companion study artifacts:

```bash
python -m src.freshness --workspace SOURCE_DIRECTORY --registry docs/registry.json --out results/refreshed-registry.json --archive results/registry-history --report results/refresh-audit.json
```

The default candidate path preserves the active frozen registry. Exit code 2 means source checks blocked replacement; inspect the audit for the per-source reason. The legacy ingestion command now archives and audits when replacing an existing output. New registries require new frozen retrieval protocols and reviewed comparison contracts before use in those earlier studies. The history filenames in the audit are relative to the chosen archive directory. Existing `load_registry` accepts a retained registry snapshot; retrieval and typed claim checks then use its historical IDs and values.

Tests exercise exact registry-byte retention, stable IDs, changed metrics, removed IDs usable with the legacy claim validator, old raw-source availability, missing prior digests, empty source collections, invalid numeric values, corrupted history refusal, blocked publication and the existing ingestion CLI. A Node smoke check exercises the browser scenario selector and local audit-file inspection when Node is available; it is not a visual browser test.

## Limitations

These are authored fault injections over synthetic envelopes containing real saved evidence, not a representative failure distribution or real-world accuracy estimate. Matching bytes establish identity relative to a saved digest, not scientific truth, freshness relative to an unobserved remote server, or protection against an adversary replacing both data and hashes. Byte-level changes include formatting and source metadata; the conservative audit can require review without any metric change. Unobserved old raw sources remain unavailable even though their registered evidence and IDs are retained.

Archival precedes publication but does not provide locking for concurrent writers, external timestamping, digital signatures or filesystem durability certification. Archive storage grows with observed revisions and has no automatic deletion policy. No runtime, infrastructure price or cost advantage was measured; no paid inference or generated-answer accuracy is involved.

## Interview understanding

Explain the difference between a record-text hash, an artifact-byte hash, a stable source ID and a versioned registry snapshot. Trace the metadata-only scenario: the scientific record stays unchanged while source bytes change, so the text baseline misses drift. Show how a removed source ID still validates its old saved metric through the historical registry. Explain why an unavailable source is unknown rather than fresh, why old raw bytes cannot be recreated from a text projection, and why hashes identify revisions without authenticating their author or validating the experiment.
