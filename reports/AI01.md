# Frozen retrieval confirmation

Can the existing ten-record evidence explorer find the requested experiment on new questions, and does better source ranking reduce the risk of treating unrelated evidence as support?

The measured answer is mixed: BM25 improves rank-1 source recall over unweighted term overlap on these authored questions, but both return evidence for every misleading lexical overlap. Empty retrieval on unrelated topics does not establish safe abstention on unsupported claims.

## Method

Before authoring confirmation questions, `experiments/AI01-freeze.json` recorded SHA-256 digests of the complete registry, `src/evidence.py` and `docs/app.js`, the ordered ten source IDs, baseline rules, cutoffs and metric definitions. The registry was neither refreshed nor edited. Full-file hashes cover titles, typed metrics, limitations and provenance as well as evidence text. A separate seal fixes both the protocol and completed question file before the first evaluation. The evaluator rejects changed inputs rather than silently treating them as the same study. These hashes detect drift; they are not an external timestamp or tamper-proof audit trail.

The existing BM25 uses lowercase ASCII alphanumeric tokens, its existing stopword set, unique query terms, title plus text, k1=1.2 and b=0.75. It retains positive scores, breaks ties by source ID and returns up to three records. There is no stemming, semantic threshold or entailment check. The baseline counts unique matching query/document terms with the same fields, tokenization, acceptance rule and tie break. Ranks 1 and 3 were specified before evaluation; neither was selected because of the results. See [Robertson and Zaragoza's BM25 reference](https://doi.org/10.1561/1500000019) for the algorithmic foundation.

`experiments/AI01-questions.json` contains 30 newly authored questions, distinct from all 13 existing studio regression questions: 20 answerable questions (two per source), four unrelated unanswerables, and six unanswerable misleading lexical overlaps. Each label includes a source-based rationale. Questions and labels were written in full before either method was run. Retrieval settings, source records, labels and question text were not changed after observing outcomes. The questions were authored with access to the source collection; independence here means no confirmation-based parameter selection, not blind authorship or a sampled user benchmark.

Source recall at k is the fraction of the 20 answerable questions whose labelled source appears in the top k. Each has one required source. Unanswerable questions never contribute a successful abstention to the recall numerator. The false support proxy is the fraction of the ten unanswerable questions returning any evidence. It flags retrieval-as-support risk, not an assertion that the retriever or an LLM generated an incorrect conclusion. A limitation that explicitly rejects a premise is useful related text but does not supply the missing measurement requested by a question. Empty retrieval is reported separately for answerable and unanswerable questions, with unsupported strata separated as well.

## Actual findings

| Measure | Frozen BM25 | Unique-term overlap |
| --- | --- | --- |
| Source recall at 1 | 20/20 (100%) | 18/20 (90%) |
| Source recall at 3 | 20/20 (100%) | 20/20 (100%) |
| False support proxy, all unanswerables | 6/10 (60%) | 6/10 (60%) |
| False support proxy, misleading overlaps | 6/6 (100%) | 6/6 (100%) |
| False support proxy, unrelated questions | 0/4 (0%) | 0/4 (0%) |
| Empty retrieval, unanswerables | 4/10 | 4/10 |
| Empty retrieval, answerable questions | 0/20 | 0/20 |

The overlap baseline ranks the volatility-break record above the stable-regime record for c17 (observed coverage) and c18 (expanding versus frozen ridge MAE). Both records share substantial methodological vocabulary. BM25 puts the expected stable-regime source first for both. This is a two-question difference, not evidence of broad statistical superiority.

Both methods return records for requests for battery voltage and cycle lifetime, measured network latency in nanoseconds, device gate fidelity, historical investment return, a post-break coverage guarantee, and calibrated default probability/funding cost. Those requested results are absent or explicitly outside the source experiments. The six failures remain in the measured ledger. Neither weighting scheme supplies a semantic abstention mechanism, so improved ranking leaves the false support proxy unchanged.

The studio's **Frozen retrieval confirmation** case exposes separate recall and unsupported-retrieval charts, both ranked source lists, labels, rationales, outcomes and CSV export. `results/AI01-confirmation.json` contains every row, aggregate numerators and denominators, strata and input fingerprints. The same measurement is included additively in `results/latest.json`; the legacy corpus, public functions, CLI and existing studio cases are retained.

## Reproduce and inspect

```bash
python -m src.confirmation --output results/AI01-confirmation.json
python lab.py --output results/latest.json
python src/studio.py --out docs/study.json
python src/studio.py --check docs/study.json
python -m unittest discover -s tests -v
python quality/contract.py --project . --name ai-research-workbench --task-id AI01
python -m http.server 8000 --directory docs
```

Open `http://localhost:8000/#confirmation` to inspect the comparison. The HTTP server is only needed for interactive viewing. Reproduction and tests run offline using the pinned project dependencies; no source refresh is needed. An optional Node check compares the existing browser retriever with Python on all 30 questions; it skips if Node is unavailable.

## Limitations and interview interpretation

This small source-aware, authored collection is not real-world accuracy, a randomized evaluation, an answer-quality assessment or evidence of generalization to other registries. Several sources are near duplicates; questions often include case descriptors. The registry snapshots synthetic simulations, not calibrated market or device observations. Confirmation evaluates retrieval over the saved artifacts, not the scientific validity of those artifacts. No generated answers, model sessions or external inference calls are involved. Baseline operation counts, runtime and infrastructure costs were not measured; no cost advantage is asserted.

For an interview, explain why corpus and rules must be fixed before confirmation, why a title or metric edit invalidates this protocol, and why source recall needs an answerable-only denominator. Be able to trace c17/c18 to the baseline's ranking failures and c25-c30 to absent measurements. Explain the difference between a source being relevant, a requested number being present, and a scientific claim being supported. A 100% source-recall result can coexist with six unsupported retrievals; neither a BM25 score nor a matching numeric transcription establishes entailment. Future retrieval changes require a separately versioned protocol and fresh questions, rather than tuning against this confirmation set.
