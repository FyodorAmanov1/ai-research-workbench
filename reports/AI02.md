# Compatible experiment comparisons

## Question

Does expanding-window ridge reduce recorded next-day squared-return test MAE compared with frozen ridge on the same saved synthetic test case? Can an evidence interface prevent arithmetic across incompatible summaries?

## Method

Use the bundled ten-record registry, without rerunning companion simulations. Both ridge methods use the same case-specific test labels from day 1451; fitting procedures differ, while evaluation is shared. The source describes seed 73, causal features, chronological boundaries, training-only normalization, and expanding refits every 60 targets. Stable and shifted cases have separate dataset identities despite sharing a seed and source artifact.

The sidecar `docs/comparison-contracts.json` reviews sixteen metrics: eight statistical-learning metrics and eight risk summaries. Each contract binds a source ID, metric label, saved value, unit, content fingerprint and source-artifact fingerprint to explicit dataset, evaluation protocol and quantity identities. These identities are curated assertions about saved cases, not raw-data provenance measurements. The registry fingerprint is checked at load time; selected values and source fingerprints are checked again during comparison. The twenty-four unreviewed metrics fail closed. Empty unit strings supply no compatibility evidence by themselves.

The gate requires finite numbers, unambiguous registered IDs and labels, explicit identical unit strings and matching reviewed identities. Unknown metrics, booleans, strings, non-finite values, missing metadata and stale contracts are rejected. No implicit unit conversion occurs. Accepted results expose left minus right and both source contracts; rejected results contain a reason and no difference. Protocol means evaluation conditions, allowing candidate and baseline training methods to differ.

The meaningful model baseline is frozen ridge. Separately, a permissive exact-unit-only comparator measures how many incompatible pairs pass a unit check. Seven authored probes exercise two accepted MAE pairs, dataset mismatch, protocol mismatch, unit mismatch, quantity mismatch and missing metadata. These are specification diagnostics, not a sampled benchmark. The protocol probe contrasts a nominal coverage design target with empirical test coverage; shared percent units do not make these procedures interchangeable. The quantity probe contrasts VaR with expected shortfall on the same risk case in USD.

Specifying intended quantities and relevant conditions follows the conceptual distinction in [JCGM VIM 2.3](https://jcgm.bipm.org/vim/en/2.3.html). Exact identifier matching is this application's conservative rule, not certification or a universal scientific comparison policy.

## Actual findings

| Saved synthetic case | Frozen ridge MAE | Expanding ridge MAE | Expanding minus frozen |
| --- | ---: | ---: | ---: |
| Stable regime | 0.4030305544093381 | 0.40378462688112504 | +0.0007540724717869374 |
| Volatility regime break | 9.190811689009081 | 9.838731697519906 | +0.647920008510825 |

Lower MAE is preferable: expanding adaptation fails to improve on frozen ridge in both saved cases. Preserve this negative finding. The source leaves MAE units empty; the implementation preserves that field and uses a reviewed next-day squared-return MAE quantity identity rather than inventing physical units. No uncertainty or significance is inferred.

All seven decisions match the authored specification: two pairs accepted, five rejected, zero incompatible pairs accepted. The unit-only baseline accepts six of seven pairs, including four incompatible pairs: cross-regime MAE, nominal versus empirical coverage, VaR versus expected shortfall, and logical-qubit versus oracle-call counts. It rejects only MAE versus percent. Failures remain in `results/AI02-comparisons.json` and the studio ledger.

The fourth studio case exposes record and metric selectors, registered values, explicit decisions, both source-artifact links, fingerprints, identities and rationales. The measured ledger retains CSV export. Browser decisions and complete accepted payloads match Python for all 1,600 ordered pairs of forty metrics, plus unknown-source and unknown-label probes. Tests also exercise missing metadata, nonnumeric values, duplicate identifiers, missing units and artifact drift. Earlier frozen retrieval cases remain reproducible.

No model generates a comparison.

## Limitations

These are arithmetic comparisons of saved synthetic summaries, not fresh simulation runs, independently verified observations, historical-market results or real-world accuracy. Only one process seed appears in the source. Summaries provide no paired residuals, uncertainty or significance test. Higher expanding MAE here does not establish a general frozen-model advantage. No runtime, computational-cost or infrastructure-price advantage was measured or assumed.

Exact equality intentionally rejects some scientifically defensible comparisons, including cross-regime sensitivity analyses and possible unit conversions. Those require separately reviewed semantics. Dataset identities are case-level assertions bound to artifacts; hashes detect accidental drift but cannot authenticate provenance against someone rewriting both data and contracts. Other metric families remain excluded until their conditions can be justified. Browser/Python parity uses Node when available; it is not a visual end-to-end browser test.

## Interview understanding

Explain why matching units is necessary but insufficient: USD quantities can measure different risks, MAEs can use different targets, and a percentage target is not observed coverage. Trace an accepted pair to saved values and identities, then compute its signed difference. Distinguish model training from evaluation so a meaningful baseline remains possible. Explain why empty units need quantity identities, missing metadata rejects rather than guesses, and a synthetic single-seed negative finding supports only a descriptive conclusion. Compatibility permits arithmetic; it does not prove causal or statistically significant improvement.
