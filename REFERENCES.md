# Primary references and implementation boundaries

[AI05](reports/AI05.md) uses Python standard-library [dataclasses](https://docs.python.org/3.12/library/dataclasses.html) for query request types and explicit runtime checks at the JSON boundary. Python [type annotations are not runtime enforcement](https://docs.python.org/3.12/library/typing.html), so malformed selectors are checked separately (official documentation links verified). Exact lookup and unknown-data codes are application contracts, not a new retrieval algorithm. Complete-record and registry-byte hashes distinguish evidence versions following the identity motivation in [W3C PROV-DM](https://www.w3.org/TR/prov-dm/) (link verified again); this is not a PROV serialization or authenticity claim.

- [BM25: The Probabilistic Relevance Framework](https://www.staff.city.ac.uk/~sbrp622/papers/foundations_bm25_review.pdf)
- [Retrieval-augmented generation](https://arxiv.org/abs/2005.11401)

The frozen confirmation protocol uses the existing BM25 formulation from Robertson and Zaragoza (2009), [The Probabilistic Relevance Framework: BM25 and Beyond](https://doi.org/10.1561/1500000019) (publisher record and author-hosted PDF verified). The unique-term-overlap comparator is specified directly in [the frozen protocol](experiments/AI01-freeze.json); it is not a claim of reproducing another retrieval system. [The confirmation report](reports/AI01.md) defines source recall and the retrieval-based false support proxy with separate denominators.

The implementation, data provenance and scope limits are documented in [the technical case study](reports/applied-study.md). Citation identifies an algorithmic foundation, not equivalence with the full paper or a claim of hardware performance.

[AI04](reports/AI04.md) reuses this BM25 foundation for a second sealed question wave (publisher DOI and author-hosted PDF verified again). Its [frozen protocol](experiments/AI04-freeze.json) additionally fixes evaluator code and defines cutoff-specific source misses as wrong-source or empty retrieval. These accounting definitions and the unique-term comparator are specified application methods, not new literature claims or estimates of generated-answer error.

The comparison contract distinguishes quantity identity and evaluation conditions as well as unit strings. The primary metrology reference is JCGM's [VIM, section 2.3: measurand](https://jcgm.bipm.org/vim/en/2.3.html), which specifies the intended quantity and its relevant conditions (link verified). This motivates explicit context; exact dataset/protocol/quantity matching is a conservative application design, not metrological certification. [AI02](reports/AI02.md) derives findings directly from the bundled source-linked registry, without a new statistical-superiority claim.

The registry refresh design separates a stable case identity from specific saved revisions. W3C's [PROV-DM, revision and entity identity](https://www.w3.org/TR/2013/REC-prov-dm-20130430/) is the primary conceptual reference (link verified): provenance must refer to the intended version when a resource changes. [AI03](reports/AI03.md) implements byte-digest checks and retained JSON snapshots; it does not claim PROV serialization conformance, authenticated provenance, or reconstruction of absent raw artifacts.
